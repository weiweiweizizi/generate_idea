# Matrix Vis Two-Stage Reconstruction Design

**状态**: 草案

**日期**: 2026-04-27

---

## 1. 背景与目标

`scripts/matrix_vis` 是 `disentangleNet` / toy basis 的后验分析模块，
目标不是做分类或训练，而是把单轴 `window diff` 还原成可解释的局部
面部运动轨迹。

当前问题背景已经明确为：

- 数据按固定长度窗口切分。
- 每个窗口、每个轴 (`x` 或 `y`) 对应一个 `window matrix`，表示该
  窗口内点对距离行为的平均结果。
- 相邻两个窗口的差分记为 `window diff`。
- 当前逆问题假定上一窗口是已知且静止的参考状态。
- 已知上一窗口起始位置 `x_i(0)`。
- 目标是根据 `window diff` 重建当前窗口内的运动轨迹。

这个问题的关键点是：

1. 观测只提供窗口级信息，不足以唯一决定逐帧轨迹。
2. 当前窗口长度 `M` 是已知的，因此输出应该仍然是长度为 `M` 的
   窗口内轨迹，而不是只输出一个静态位移总结。
3. 由于输入是弱观测，重建必须是优化式的，而不是闭式逆解。

因此，本设计采用两阶段路线：

- Stage A: 先把 `window diff` 投影到一个可实现的窗口结构目标上。
- Stage C: 再用少量全局共享单调时间基，生成窗口内轨迹。

---

## 2. 设计目标

### 2.1 必须做到

- 明确区分 `window matrix`、`window diff`、窗口结构目标、窗口轨迹。
- 提供一个显式的结构投影阶段，并输出 `structural residual`。
- 用 2 到 4 个全局共享单调时间基生成窗口内轨迹。
- `x` / `y` 两轴按轴独立求解，但共享同一种时间基族。
- 约束必须与“窗口内不反向”的假设一致。
- 明确废弃基于点 ID 的全局顺序约束。

### 2.2 明确不做

- 不将单个 `window diff` 当作可唯一逆出的逐帧真值。
- 不使用“每个点一条完全自由曲线”的过强参数化。
- 不再依赖点 ID 顺序作为几何顺序。
- 不把 `basis` 幅值标定作为当前阶段的核心问题。
- 不将 toy 结果当作真实逆问题正确性的证明。

---

## 3. 总体方案

两阶段流程如下。

### 3.1 Stage A: 结构目标恢复

输入：

- 上一窗口已知初始位置 `x_i(0)`
- 当前单轴 `window diff`

输出：

- `D_raw`
- 可实现的结构代理 `z`
- 投影后的结构矩阵 `D_hat`
- `structural residual`

Stage A 的职责不是生成轨迹，而是先回答：

> 当前窗口的平均结构，最接近什么样的可实现状态？

### 3.2 Stage C: 窗口内轨迹生成

输入：

- Stage A 的结构代理 `z`
- Stage A 的投影结构 `D_hat`
- 上一窗口初始位置 `x_i(0)`

输出：

- 长度为 `M` 帧的单轴轨迹
- 轨迹拟合误差
- 平均结构对齐误差

Stage C 的职责是：

> 在不反向、单调推进的前提下，生成一个符合窗口结构目标的可解释轨迹。

---

## 4. Stage A 设计

### 4.1 已知量

- 上一窗口初始位置 `x_i(0)`
- 当前窗口差分矩阵 `ΔD`

### 4.2 上一窗口平均结构

[
D_{\text{prev}}(i, j) = |x_j(0) - x_i(0)|
]

### 4.3 原始结构目标

[
D_{\text{raw}} = D_{\text{prev}} + \Delta D
]

### 4.4 结构投影

`D_raw` 一般不能直接保证可实现，因此需要求一个最近的结构代理 `z`
和对应的可实现结构 `D_hat`。

Stage A 可以形式化为：

[
z = \arg\min_z \mathcal{L}_{struct}(z; D_{\text{raw}}, x(0))
]

其中 `\mathcal{L}_{struct}` 应至少包含：

- pairwise distance fit
- 对上一窗口位置的适度参考
- 可实现性相关的正则或投影项

### 4.5 Structural Residual

Stage A 必须输出结构残差，用于判断输入是否已经偏离可实现集合太远。

建议至少输出：

- `structural_residual_rmse`
- `structural_residual_heatmap`
- `pairwise_consistency_stats`

这一步是后续诊断的关键基础。

---

## 5. Stage C 设计

### 5.1 轨迹参数化

窗口内轨迹采用少量全局共享单调时间基：

[
x_i(t_m) = x_i(0) + \sum_{k=1}^{K} a_{ik}\,\phi_k(t_m), \quad K = 2 \sim 4
]

推荐默认 `K = 3`。

### 5.2 时间基约束

当前采用固定解析基，要求：

- `phi_k(0) = 0`
- `phi_k(t)` 单调不减
- `phi_k` 不表达回摆
- `phi_k` 在 `x` / `y` 两轴中共用

可优先采用的基族：

- `early-rise`
- `linear`
- `late-rise`

### 5.3 设计理由

这样做的原因是：

- 当前问题背景已确认“窗口内不反向”
- 共享单调基比单一包络更灵活
- 比每点完全自由曲线更可识别
- 适合 `x/y` 分轴再合成的流程

---

## 6. Stage C 目标函数

### 6.1 平均距离拟合

Stage C 的主数据项直接拟合窗口平均距离目标：

[
\mathcal{L}_{data}
=
\sum_{i<j} w_{ij}
\Big(
\frac{1}{M}\sum_{m=0}^{M-1} |x_j(t_m)-x_i(t_m)|
- D_{\hat{}}(i,j)
\Big)^2
]

其中 `D_hat` 来自 Stage A。

### 6.2 平均位置对齐

[
\mathcal{L}_{mean}
=
\sum_i
\Big(
x_i(0) + \sum_{k=1}^{K} \mu_k a_{ik} - z_i
\Big)^2
]

其中：

[
\mu_k = \frac{1}{M}\sum_{m=0}^{M-1} \phi_k(t_m)
]

### 6.3 幅值正则

[
\mathcal{L}_{amp} = \sum_{i,k} a_{ik}^2
]

### 6.4 空间平滑

不要再使用基于点 ID 的全局顺序约束。  
改为在嘴部局部邻接图 `E` 上施加平滑：

[
\mathcal{L}_{spatial}
=
\sum_{(i,j)\in E}\sum_k (a_{ik} - a_{jk})^2
]

---

## 7. 约束设计

### 7.1 保留的约束

- anchor 点系数固定为 0
- 单调时间基
- 系数符号与 Stage A 位移方向一致
- 必要时加位移边界

### 7.2 符号一致性

设：

[
d_i = z_i - x_i(0)
]

则：

- 若 `d_i > eps`，约束 `a_{ik} >= 0`
- 若 `d_i < -eps`，约束 `a_{ik} <= 0`
- 若 `|d_i| <= eps`，仅靠正则项压小

### 7.3 明确废弃的约束

- 基于点 ID 的全局顺序约束
- `x_{i,m} <= x_{i+1,m}` 这类全局不可交叉约束
- 将点 ID 顺序误当作几何顺序

这是因为实际过程中已经确认：

- 这个假设过强
- 它不适合当前数据和当前建模目标

---

## 8. 分轴策略

当前仍采用按轴分别求解：

- `x` 单独重建
- `y` 单独重建
- 最后再 compose 成 2D 轨迹预览

这样做是因为：

- 输入和 basis 本来就是按轴组织的
- 单轴问题更容易诊断
- 两轴可共享同一组时间基族，但系数独立

---

## 9. 诊断与输出

建议每次重建至少输出：

- `resolved_config.yaml`
- `D_raw`
- `D_hat`
- `structural_residual_rmse`
- `structural_residual_heatmap`
- `trajectory_fit_rmse`
- `mean_alignment_rmse`
- `sign_conflict_count`
- `solution.npz`
- `summary.json`

其中 `structural_residual` 是第一优先级诊断指标。

---

## 10. Toy 数据的定位

toy 数据只用于验证：

- 配置能否读通
- 求解链路能否跑通
- 导出和 compose 是否正常

它不用于证明真实问题假设已被验证。

---

## 11. 实现边界

本次落地只修改算法本身，不扩展 `matrix_vis` 的框架边界。

具体约束如下：

- 继续使用之前已经生成的 toy data。
- 不改 `matrix_vis` 的现有目录框架和接入框架。
- 不把 `disentangleNet` 的真实分析产物接入进来。
- 不重做配置系统、CLI 框架或导出框架。
- 只改 Stage A / Stage C 相关的建模、目标函数、约束和诊断。

实现阶段的重点会是：

- 重写重建算法
- 重写与算法强相关的诊断输出
- 保持现有 toy 闭环可运行

---

## 12. 与现有实现的差异

与早期版本相比，这次设计明确改变了以下点：

- 不再将 `window diff` 直接视为帧级轨迹真值
- 不再保留基于点 ID 的顺序约束
- 不再把单一共享包络当作时间模型
- 不再把 `lambda_vel` 作为“速度变化小”的模糊说法
- 不再把 toy 成功误读为真实问题已闭合

---

## 13. 关键结论

`matrix_vis` 的重建问题应被理解为：

> 先将窗口差投影到一个可实现结构上，再用少量共享单调时间基生成窗口内轨迹。

这比“从 basis 直接逆出唯一真实轨迹”更符合当前问题背景，也更符合可诊断、可迭代的研究路径。
